# Memory

## 关键教训

- **parseKeypress 对普通字符返回 name:''**: 符号（`/`, `.`, `-`, `!` 等）和多字符 buffer 都返回 `name: ''`、`isPrintable: undefined`。printable 判断不能用 `name.length === 1`，要用排除法（排除 return/enter/tab/escape/backspace）
- **parseKeypress 必须逐字符调用**: 传多字符 buffer 时 `sequence` 包含整个 buffer，导致 `sequence.length > 1`，字符被吞。非 ESC 字符必须逐个传，只有 ESC 序列才传完整 buffer
- **Shift+Enter 序列因终端而异**: Ghostty 用 `CSI 27;2;13~`（name:''），Kitty tilde 用 `CSI 13;2~`（被误识别为 f3+shift），Kitty u-format 用 `CSI 13;2u`（正确识别为 return+shift）。onKeypress 需 normalize 所有变体为 `{name:'return', shift:true}`

## 经验教训

- **MinerU 输出路径**: `/tmp/pc2-pdf/{stem}/hybrid_auto/{stem}.md`，不是直接在 output-dir 下
- **bash tool timeout 需可配置**: MinerU 处理一个 3 页 PDF 需要 30-40 秒，30s 默认超时会杀掉进程。bash tool 已改为接受 `timeout` 参数（默认 30s，最大 600s）
- **实现新功能时，先写失败测试再写实现**：TDD red-green-refactor 流程。测试先行能暴露接口设计问题，避免写完实现才发现接口不好测。已在 `context-assembly-fix` 计划中验证有效。
- **Agent loop 不得因 LLM 纯文本回复终止**：`!hasTools` 仅表示本轮无工具调用，不等于任务完成。改为连续 3 轮无工具调用才视为 `stalled`，真正退出靠 `ask_user`、`anti_loop`、`max_rounds`、`timeout`
- **反循环检测必须硬退出**：`consecutiveFailures >= antiLoopThreshold(3)` 不只是警告，必须 `yield { type: 'done', reason: 'anti_loop' }` 终止循环
- **skill 中的 Bash pattern 需解析命令链**：`isAllowedBySkill` 对 `cmd` 按 `&&` 和 `;` 分割后逐段匹配，使 `source env && uv pip install` 能匹配 `uv*`

## 命名规范

文件名统一用 kebab-case：`memory-search.ts`、`turn-end-callback.ts`、`memory-and-context.md`。

| 范围 | 规则 | 示例 |
|------|------|------|
| 文件名（.ts, .md, .json 等） | kebab-case | `memory-search.ts`, `agent-loop.ts` |
| 变量、函数、类型、接口 | camelCase | `turnEndCallback`, `memorySearch` |
| 常量、环境变量 | UPPER_SNAKE_CASE | `MAX_ROUNDS`, `FREEZE_THRESHOLD` |

## 关键决策

- **BAML 函数参数之间必须用逗号分隔**：`function Foo(a: string, b: string)` 不加逗号会导致 "This line is invalid" 编译错误
- **BAML 不支持在同一文件中将引用数组类型的 class 与 function 混用**：如果一个 class 有 `field OtherClass[]`，则同文件中不能定义 function。解决方案：class 和 function 分文件
- **BAML client 名称必须大写开头**：`Glm5Turbo` 而非 `glm_5_turbo`
- **BAML generator output_dir** 设为 `..` (项目根目录)，BAML 会自动在 output_dir 下创建 `baml_client/` 子目录
- **BAML ToolCall.arguments 是 string**（LLM 原始输出），应用层 ToolCall.arguments 是 `Record<string, unknown>`（解析后）。两套类型不混用
- **cron-parser v5 API**: 使用 `CronExpressionParser.parse()` 而非 `parseExpression()`（已弃用）
- **tsconfig rootDir 设为 `.`**: 因为 baml_client/ 在 src/ 外面，需要 `"rootDir": "."` 并 include `["src/**/*", "baml_client/**/*"]`
- **BAML class+function 分文件**: class 定义在 types.baml / memory-types.baml / verify-types.baml，function 定义在单独的 .baml 文件中
- **GLM API + BAML openai-generic**: 必须设置 `default_role "user"`，否则 BAML 默认把 prompt 放 system role，GLM 会报 `messages 参数非法`（400 错误码 1214）
- **BAML test 语法**: `test TestName { functions [FuncName] args { param1 "value" } }`，用 `baml-cli test --from baml_src` 运行，需要有效的 API key 和余额
- **cron-parser `.next()` 返回未来时间**: 不能用 `next <= now` 判断是否到期，必须用 `.prev()` 获取上一个调度时间，再与 lastRun 比较
- **tiktoken singleton 必须用 promise-based**: 不能用 `_encoder: X | null`，并发调用会竞争。用 `_encoderPromise: Promise<X> | null`，赋值是同步的，JS 单线程保证无竞争
- **js-yaml 必须用 JSON_SCHEMA**: `yaml.load(str, { schema: yaml.JSON_SCHEMA })`，否则 `!!js/function` 可注入代码
- **file tool 必须做 path sandbox**: `isPathWithinRoot()` 用 `resolve()` + `startsWith()` 检查路径不超出 workspace
- **bash tool isReadOnlyCommand 必须在 execute() 中调用**: 不能只在导出函数中定义但不在 execute 中使用
- **checkAndFreeze 必须串行化**: 用 `Map<string, Promise<boolean>>` promise chain，防止并发调用生成相同文件名
- **~~messages 字符串必须有 token budget~~**（已被 context assembly 替代）：loop 中每轮从磁盘组装 context，暴力截断已移除。见 `docs/superpowers/plans/2026-04-29-context-assembly-fix.md`
- **写入操作必须同时实现对应的读取操作**：freeze/summarize 写磁盘后，必须在运行时（loop）中读回使用，否则写入无效。数据流必须闭环
- **ReflectRunner 必须有 task consumer**: 只 push 不 consume 的 queue 是死代码。用 `onTask` callback + `processQueue()` 消费
- **Agent loop 终止模型**: `maxRounds=1000` 是绝对安全兜底，真正终止靠 4 个信号——`ask_user`(用户交互)、`anti_loop`(同工具连续失败 ≥ 3 次)、`stalled`(连续 3 轮无工具调用)、`timeout`。LLM 纯文本回复不终止循环。
